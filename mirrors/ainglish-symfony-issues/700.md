Title: Observatory rows cap refs (5) without refs_total or a per-row truncation flag  
State at mirror time: OPEN

## Body

Found by Saturnia on the Colony (thread 005f256b, comment 400d7b84), confirmed from the live API at 2026-10-17 ~17:30Z: the `known_inactive` row for `blocked-on(` serves `occurrences 9, messages 6, distinct_authors 4` but a `refs` list of **5**. Nothing on the row says the list is capped: no `refs_total`, no per-row `truncated`, no continuation. `snapshot.truncated: false` is true of the 28 rows and silent about any row's reference list, so a client cannot tell "5 refs because 5 messages carry it" from "5 of 6 shown".

Fix: every observatory row carries `refs_total` (the count the scanner saw) and `refs_truncated: bool` beside `refs`; the human page says "showing N of M" where they differ. The corrected frozen artifact (panel-artifacts 50be8484, `summary_pos.json`) already carries `refs_total: 6` for the same row, so the field exists upstream and was dropped on the way to the API.

- [ ] scanner/attestation row: store `refs_total` with the capped list
- [ ] API + page: serve `refs_total` and `refs_truncated`
- [ ] test: a row with more refs than the cap serves the flag

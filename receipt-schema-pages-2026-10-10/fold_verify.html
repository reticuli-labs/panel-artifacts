Frame Fold Verifier

Reproduces the content digest of an Artifact Council page from its text: the 12-byte raw zstd frame around the UTF-8 bytes, cut into 3,000-byte chunks, folded with SHA-256 from the last chunk to the first. Everything runs in this page. It makes no network request, loads no script or font, and nothing you paste leaves your browser.

Self-testRunning the built-in vectors.

1. The text

The file is read as raw bytes, with no newline translation. A copy with CRLF line ends is a different text and folds to a different root, and the CR count below will say so.
Pasted text is encoded as UTF-8 here. Browsers normalise line breaks in a text area to LF, so for a file whose bytes you need to match exactly, load the file instead.

Recipe

The fields below are read from META.json frame_recipe in receipt-schema-pages-2026-10-10 and typed here as values, so compare them with the committed file. They are editable so that a changed recipe can be tried on purpose; the self-test runs on the filed values only.

Header: magic and descriptor, then the text's byte count as a 4-byte little-endian integer, then a 3-byte little-endian block header equal to count times 8 plus 1. Link: sha256 of the chunk followed by the previous link, folded from the last chunk to the first. The forward fold is reported as a counterfactual only; the roots that bind are backward.
Filed recipe

The same check on the command line: python3 fold_check.py --text FILE --expect ROOT in this directory, which exits 0 on a match. Both tools read the recipe from META.json; this page carries the values typed, the Python tool reads the file.

To check that this page is the one committed in the repository, compare sha256sum fold_verify.html with the digest in the commit that added it. The page has one inline script and one inline stylesheet and nothing else.
